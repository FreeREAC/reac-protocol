## Instrument, and how absence was made checkable

- Corpus: `/home/pau/Devel/audio/reac-captures`, **107 pcap files, 4 999 280 REAC frames**
  read end to end (a tag-aware reader; the 2026-09 sessions are 802.1Q VLAN 12).
- Every "not found" below is paired with a **positive control in the same scan**. The first
  version of the op-`0403` detector matched `block[4] == 3`, which is the REAC wrapper byte, not
  the segment — it reported **0 records in all 107 files**. `libreac`'s `headamp_trace` on the
  same file found 2 021, which is what exposed the bug. Read every zero in this note as
  "the same pass found the control".
- Tools: a copy of `libreac` built with `make wire-tools` in
  `/tmp/.../scratchpad/libreac-copy` (the libreac tree itself was not touched), plus purpose-built
  readers in the scratchpad. `wire_census` carries its own guard and prints
  `no REAC frame — an empty scan is not a result`.
- **Capture-length caveat, not a protocol fact.** In several sessions each talker's frames split
  ~50/50 between the documented length and that length **+2** (1492/1494 downstream, 628/630 and
  340/342 upstream), the two extra bytes sitting *after* the `c2 ea` end marker and varying per
  frame. Three different devices alternating frame length in lockstep is far more consistent with
  the capture path than with three FPGAs. Treated as an instrument artefact throughout; the
  `c2 ea` tail rule is unaffected. **OPEN**: settle by taking one session on two taps at once.

## Candidates discarded, and why

Four candidates were written and then thrown away on the second pass against the source. They
are recorded so nobody re-derives them.

1. **"An S-1608 in master mode never grants."** Measured: zero op-`0403` records in 300 000
   frames of `headamp-m200-48k-2026-09-11/…-session-start-30s.pcap`. Discarded on re-reading
   `wire-format.md:316` (correction dated **2026-09-09**): a box on M grants *only by echoing a
   joining box's own records*, and no join happens inside that window — reac-pw had already
   joined before the capture opened. The zero is consistent with the corrected model, not
   against it. Only the 1/s `cfea` cadence survived, as #31.
2. **"The M-200 emits 1494-byte frames, contradicting the 1492 geometry."** Discarded: the
   1492/1494 split is ~50/50 (909 vs 897; 969 vs 968) and appears simultaneously on the box's
   628/630 and 340/342 frames from *different devices* in the same file, with the extra bytes
   after the `c2 ea` marker. That is a capture path, not three FPGAs in lockstep. Demoted to
   the instrument caveat.
3. **"An M-5000 has been captured at 48 kHz"** (from a 254 µs median gap in
   `m5000-s0808-96k-mirror__matrix-m5000-s0808-2026-07-11.pcap`). Discarded: that file is a
   **distilled** capture with sampled filler, so its inter-frame median measures the distiller,
   not the desk — and its `cfea` byte reads the 96 kHz code. #23 stands.
4. **"`XVSCEN` is not on the wire."** Discarded: the scan covered only the first 50 bytes of each
   frame, so it could not have found a tag living in the scene bulk. An absence a search could
   not have detected is not a result. Recorded OPEN as #11 with the search that would settle it.

Two further candidates were **re-scoped** rather than dropped. The channel-info finding (#9) was
first written as "the section is wrong"; re-reading it showed the flag byte is a parenthetical
and the section's main claim is right, so only the parenthetical is refuted. The ENROLL finding
(#24) was first written as "the width rule is refuted"; checking the MANIFEST's ledger
(`group_map 107 → 107, identical`) against the 107 frames actually read showed the absence is
complete but bears only on the **evidence claim** for the 16-channel row, not on the rule, which
the 8- and 32-wide rows do support.
